# 001 — Ingestion: Spec

**Status:** Done · **Roadmap:** 001 · **Decisions:** 002–006, 008

## Goal

Turn an uploaded document into searchable chunks stored in ChromaDB, so later steps can
retrieve them and cite where they came from.

## User story

As a user, I upload a PDF, Markdown, or text file, and rag-dog indexes it so I can ask
questions about it. If I upload the same file again, nothing is duplicated.

## In scope

- File types: `.pdf`, `.md`, `.txt`
- Content-hash dedup: identical files are ingested once
- Page-aware chunking so citations can name a page
- Persistent storage across restarts

## Out of scope (v1)

- Scanned PDFs / OCR
- Tables and multi-column layout fidelity
- Replacing old chunks when an updated file with the same name is uploaded
- Chunks that span page boundaries
- Upload UI (roadmap 004) — this spec covers the core functions only

## Data model

Each chunk is one record in the ChromaDB collection.

| Field | Value |
|---|---|
| `id` | `f"{doc_hash}:{chunk_index}"` |
| `document` | chunk text |
| `embedding` | generated by ChromaDB's default model |
| `metadata.doc_hash` | SHA-256 of the file's bytes (hex) |
| `metadata.filename` | original filename |
| `metadata.file_location` | path to the stored original |
| `metadata.chunk_index` | position of the chunk in the document (0-based) |
| `metadata.page` | page number (1-based; `1` for `.md` / `.txt`) |
| `metadata.embedding_model` | `all-MiniLM-L6-v2` |

Collection: persistent, cosine distance (set at creation; can't be changed later).

## Acceptance criteria

1. Ingesting a supported file stores ≥ 1 chunk with all metadata fields above.
2. Ingesting the same file twice stores its chunks once; the second call returns `0`.
3. The same file under a different name is recognized as a duplicate.
4. Every chunk is ≤ the configured chunk size, and neighbouring chunks overlap.
5. Every PDF chunk carries the correct page number.
6. Chunks survive a process restart.
7. Unsupported file types are rejected with a clear error.
8. A large file (≥ 100 MB) hashes without loading it fully into memory.

## Constraints

- Chunk size must fit the embedding model's ~256-token input limit.
- `ragdog/core/` has no UI or HTTP imports.
